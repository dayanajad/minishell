## 🧮 **BODMAS in Math:**

```
B - Brackets     ()
O - Orders       ^
D - Division     ÷
M - Multiplication ×
A - Addition     +
S - Subtraction  -
```

**Example:**
```
2 + 3 × 4

Wrong: (2 + 3) × 4 = 20
Right: 2 + (3 × 4) = 14

Why? Multiplication before addition!
```

---

## 🐚 **"BODMAS" for Shell (Operator Precedence):**

```
1. ( )          Parentheses (highest priority)
2. |            Pipe
3. &&           AND
4. ||           OR (lowest priority)
```

---

## 📊 **Examples (Just Like BODMAS):**

### **Example 1:**
```bash
ls && cat file.txt || echo "failed"
```

**How to parse:**
```
Find || first (lowest precedence)
Split: [ls && cat file.txt] || [echo "failed"]
       ^^^^^^^^^^^^^^^^^^^
       Now parse this part

Find && 
Split: [ls] && [cat file.txt]

Final tree:
         ||
        /  \
      &&    echo
     /  \
    ls   cat
```

**Like math:**
```
2 + 3 × 4
      ^^^
      Do this first

2 + 12 = 14
```

### **Example 2:**


```
Split: [(ls && pwd)] || [echo "failed"]

Inside ():
Find &&
Split: [ls] && [pwd]

Final tree:
         ||
        /  \
     GROUP  echo

      &&
     /  \
    ls  pwd
```

```
(2 + 3) × 4

 Do this first
```

## 🎯 **The Parsing Algorithm (Like BODMAS):**

### **In Math:**
```c
// Parse: 2 + 3 × 4

1. Look for lowest precedence operator: +
2. Split: left=[2], right=[3 × 4]
3. Recursively parse right side:
   - Look for ×
   - Split: left=[3], right=[4]
4. Build tree:
       +
      / \
     2   ×
        / \
       3   4
```

### **In Shell:**
```c
// Parse: ls && cat | grep

1. Look for lowest precedence: &&
2. Split: left=[ls], right=[cat | grep]
3. Recursively parse right side:
   - Look for |
   - Split: left=[cat], right=[grep]
4. Build tree:
       &&
      /  \
    ls    |
         / \
       cat grep
```

## 💻 **The Code (Recursive Descent Parser):**

### **Math Parser:**
```c
// Parse expression with precedence

Node *parse_addition() {
    Node *left = parse_multiplication();  // Higher precedence first
    
    if (current_token == '+' || current_token == '-') {
        Node *node = new_node(current_token);
        node->left = left;
        node->right = parse_addition();  // Recursion
        return node;
    }
    
    return left;
}

Node *parse_multiplication() {
    Node *left = parse_number();  // Highest precedence (operands)
    
    if (current_token == '*' || current_token == '/') {
        Node *node = new_node(current_token);
        node->left = left;
        node->right = parse_multiplication();
        return node;
    }
    
    return left;
}
```

### **Shell Parser (SAME PATTERN!):**
```c
// Parse commands with precedence

t_ast *parse_or() {
    t_ast *left = parse_and();  // Higher precedence first
    
    if (current_token == OR) {
        t_ast *node = new_node(NODE_OR);
        node->left = left;
        node->right = parse_or();  // Recursion
        return node;
    }
    
    return left;
}

t_ast *parse_and() {
    t_ast *left = parse_pipe();  // Even higher precedence
    
    if (current_token == AND) {
        t_ast *node = new_node(NODE_AND);
        node->left = left;
        node->right = parse_and();
        return node;
    }
    
    return left;
}

t_ast *parse_pipe() {
    t_ast *left = parse_group();  // Highest precedence
    
    if (current_token == PIPE) {
        t_ast *node = new_node(NODE_PIPE);
        node->left = left;
        node->right = parse_pipe();
        return node;
    }
    
    return left;
}

t_ast *parse_group() {
    if (current_token == LPAREN) {  // (
        eat_token();  // consume '('
        t_ast *node = parse_or();  // Start from lowest precedence again!
        eat_token();  // consume ')'
        return node;
    }
    
    return parse_command();  // Base case: actual command
}
```

## 📚 **Precedence Table Comparison:**

### **Math (BODMAS):**
```
Priority 1 (highest): ( )
Priority 2:           ^ (power)
Priority 3:           × ÷
Priority 4:           + -
Priority 5 (lowest):  none
```

### **Shell:**
```
Priority 1 (highest): ( )
Priority 2:           |
Priority 3:           &&
Priority 4 (lowest):  ||
```

---

## 🎓 **Why This Order?**

### **Math Logic:**
```
Multiplication "binds tighter" than addition

3 + 4 × 5
      ^^^  These numbers "belong together" more

= 3 + 20
= 23
```

### **Shell Logic:**
```
Pipes "bind tighter" than logical operators

cat | grep && wc
    ^^^^^^  These commands "belong together" more

= (cat | grep) && wc
```

**Makes sense!** Pipes connect data flow, so they should be grouped first.
