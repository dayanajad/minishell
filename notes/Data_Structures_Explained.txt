This document explains all the data structures defined in minishell.h
and how they work together.

═══════════════════════════════════════════════════════════════════
1. t_token - Token Structure (Lexer Output)
═══════════════════════════════════════════════════════════════════

typedef struct s_token
{
    t_token_type    type;      // Type of token (WORD, PIPE, REDIR, etc.)
    char            *value;    // The actual string value
    struct s_token  *next;     // Next token in the list
    struct s_token  *prev;     // Previous token (for easy traversal)
}   t_token;

PURPOSE: Represents a single token from the input string.

EXAMPLE INPUT: echo "hello" | cat > output.txt

RESULTING TOKEN LIST:
┌─────────┬─────────┐    ┌─────────┬─────────┐    ┌─────────┬─────────┐
│ WORD    │ "echo"  │ -> │ WORD    │ "hello" │ -> │ PIPE    │ "|"     │ ->
└─────────┴─────────┘    └─────────┴─────────┘    └─────────┴─────────┘
┌─────────┬─────────┐    ┌─────────┬─────────┐    ┌─────────┬─────────┐
│ WORD    │ "cat"   │ -> │ REDIR_  │ ">"     │ -> │ WORD    │ "output"│
│         │         │    │ OUT     │         │    │         │ ".txt"  │
└─────────┴─────────┘    └─────────┴─────────┘    └─────────┴─────────┘

═══════════════════════════════════════════════════════════════════
2. t_redir - Redirection Structure
═══════════════════════════════════════════════════════════════════

typedef struct s_redir
{
    t_redir_type    type;      // REDIR_IN, REDIR_OUT, APPEND, HEREDOC
    char            *file;     // Filename or heredoc delimiter
    int             fd;        // File descriptor (set during execution)
    struct s_redir  *next;     // Next redirection
}   t_redir;

PURPOSE: Stores information about file redirections.

EXAMPLE: cmd < input.txt > output.txt

REDIRECTION LIST:
┌──────────────┬────────────┬──────┐    ┌──────────────┬────────────┬──────┐
│ REDIR_IN     │ "input.txt"│ fd=3 │ -> │ REDIR_OUT    │ "output.txt│ fd=4 │
└──────────────┴────────────┴──────┘    └──────────────┴────────────┴──────┘

═══════════════════════════════════════════════════════════════════
3. t_cmd - Command Structure
═══════════════════════════════════════════════════════════════════

typedef struct s_cmd
{
    char            **args;    // NULL-terminated array of arguments
    t_redir         *redirs;   // Linked list of redirections
    struct s_cmd    *next;     // Next command in pipeline
}   t_cmd;

PURPOSE: Represents a single command with its arguments and redirections.

EXAMPLE: echo hello | grep h | wc -l

COMMAND PIPELINE:
┌─────────────────────────────────────┐
│ t_cmd #1                            │
│ args: ["echo", "hello", NULL]      │
│ redirs: NULL                        │
│ next: ────────────────────────────┐ │
└───────────────────────────────────┘ │
                                      ↓
┌─────────────────────────────────────┐
│ t_cmd #2                            │
│ args: ["grep", "h", NULL]          │
│ redirs: NULL                        │
│ next: ────────────────────────────┐ │
└───────────────────────────────────┘ │
                                      ↓
┌─────────────────────────────────────┐
│ t_cmd #3                            │
│ args: ["wc", "-l", NULL]           │
│ redirs: NULL                        │
│ next: NULL                          │
└─────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════
4. t_env - Environment Variable Structure
═══════════════════════════════════════════════════════════════════

typedef struct s_env
{
    char            *key;      // Variable name (e.g., "PATH")
    char            *value;    // Variable value
    struct s_env    *next;     // Next environment variable
}   t_env;

PURPOSE: Stores environment variables as a linked list.

EXAMPLE:
┌─────────┬────────────────────────┐    ┌─────────┬────────────┐
│ "PATH"  │ "/usr/bin:/bin"        │ -> │ "HOME"  │ "/home/usr"│ -> ...
└─────────┴────────────────────────┘    └─────────┴────────────┘

═══════════════════════════════════════════════════════════════════
5. t_shell - Main Shell State
═══════════════════════════════════════════════════════════════════

typedef struct s_shell
{
    t_env   *env;              // Environment variables (linked list)
    char    **envp;            // Environment array for execve()
    int     exit_status;       // Last command exit status ($?)
    int     stdin_backup;      // Backup of original stdin
    int     stdout_backup;     // Backup of original stdout
    int     pipe_count;        // Number of pipes in current command
}   t_shell;

PURPOSE: Holds all global shell state that persists between commands.

USAGE:
- env: Used for variable expansion ($VAR)
- envp: Passed to execve() when running external commands
- exit_status: Used for $? expansion
- stdin_backup/stdout_backup: Restore original FDs after redirections
- pipe_count: Used for pipe management

═══════════════════════════════════════════════════════════════════
DATA FLOW OVERVIEW
═══════════════════════════════════════════════════════════════════

User Input: "echo hello | grep h > output.txt"
     │
     ↓
┌────────────────────────────────────────────────────────────────┐
│ LEXER (Partner A)                                              │
│ Breaks input into tokens                                       │
└────────────────────────────────────────────────────────────────┘
     │
     ↓
t_token list: [WORD:"echo"] -> [WORD:"hello"] -> [PIPE:"|"] ->
              [WORD:"grep"] -> [WORD:"h"] -> [REDIR_OUT:">"] ->
              [WORD:"output.txt"]
     │
     ↓
┌────────────────────────────────────────────────────────────────┐
│ PARSER (Partner A)                                             │
│ Groups tokens into commands                                    │
└────────────────────────────────────────────────────────────────┘
     │
     ↓
t_cmd list:
  cmd1: args=["echo", "hello", NULL], redirs=NULL
        ↓
  cmd2: args=["grep", "h", NULL], redirs=[REDIR_OUT:"output.txt"]
     │
     ↓
┌────────────────────────────────────────────────────────────────┐
│ EXECUTOR (Partner B)                                           │
│ Executes the command pipeline                                  │
└────────────────────────────────────────────────────────────────┘
     │
     ↓
OUTPUT: "hello" written to output.txt

═══════════════════════════════════════════════════════════════════
ENUMS EXPLAINED
═══════════════════════════════════════════════════════════════════

t_token_type:
-------------
TOKEN_WORD         - Regular word/argument
TOKEN_PIPE         - | character
TOKEN_REDIR_IN     - < character
TOKEN_REDIR_OUT    - > character
TOKEN_REDIR_APPEND - >> characters
TOKEN_HEREDOC      - << characters
TOKEN_ENV_VAR      - $VAR (may not be needed if expanded during lexing)
TOKEN_DQUOTE       - " character (for quote tracking)
TOKEN_SQUOTE       - ' character (for quote tracking)
TOKEN_EOF          - End of input

t_redir_type:
-------------
REDIR_IN       - Input redirection (<)
REDIR_OUT      - Output redirection (>)
REDIR_APPEND   - Append redirection (>>)
REDIR_HEREDOC  - Heredoc (<<)

MEMORY MANAGEMENT NOTES
═══════════════════════════════════════════════════════════════════

IMPORTANT: You MUST free all allocated memory!

Who allocates what:
-------------------
LEXER allocates:   t_token structures and token values
PARSER allocates:  t_cmd structures, args arrays, t_redir structures
ENV allocates:     t_env structures, key/value strings
EXECUTOR:          May allocate temporary strings

Who frees what:
-------------------
After execution:   Free ALL commands, redirections, tokens
On shell exit:     Free environment list, close file descriptors
On error:          Free everything and exit cleanly

GLOBAL VARIABLE
═══════════════════════════════════════════════════════════════════

extern int g_signal;

PURPOSE: The ONLY allowed global variable.
USAGE:   Store signal number when Ctrl-C is pressed
WHY:     Signal handlers can't access main data structures
         This variable lets you know a signal was received

IMPORTANT: Don't store any other information in globals!

TIPS FOR IMPLEMENTATION
═══════════════════════════════════════════════════════════════════

1. Start with simple cases:
   - Single command with no pipes/redirections
   - Then add pipes
   - Then add redirections
   - Finally add quotes and variable expansion

2. Test each structure independently:
   - Test lexer output by printing tokens
   - Test parser output by printing command structures
   - Test executor with hardcoded commands first

3. Memory management:
   - Use valgrind CONSTANTLY
   - Free in reverse order of allocation
   - Set pointers to NULL after freeing

4. Error handling:
   - Check all malloc() returns
   - Check all system call returns
   - Clean up before exiting on error

Good luck! 🚀
